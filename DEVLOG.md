# Development log

## 2026-07-28

Refined the commit-reveal dispute spec with two findings adopted from cross-checking the published Xaya blinded-sighting-test paper and its reference implementation (xaya/fog-of-war). Flight bodies in the channelized profile are now committed as Merkle roots, so an on-chain dispute can prove a single named element with a log-depth path instead of shipping the whole flight; the GSP-arbitrated profile skips this since it doesn't need it. The spec also now explains why dummy padding stays scoped per turn rather than per game: a mid-game dispute would expose game-scoped dummies for all remaining turns, and the precompute benefit can be recovered by hashing future turns' dummies during idle time. The paper is cited as the published form of the security review, and it credits this repo as its starting point.

**Decisions & notes:** Merkle commitments are profile-specific (channelized only); dummies remain per-turn by design, with idle-time precompute as the mitigation.

## 2026-07-27

A landmark day that took the project from a prototype with known protocol breaks to a hardened, tested, CI-backed library with the first phase of a dispute layer. It started by fixing the two vulnerabilities reported in issues #1 and #2: hash-to-group had mapped elements as H(x)*G, giving every element a known discrete log (one honest run let a participant enumerate the counterparty's whole set offline), and the wire messages carried elements in cleartext alongside their blinded values. The core now runs on ristretto255 via libsodium (Elligator 2 mapping, no OpenSSL dependency), and wire messages carry only blinded points and authenticated data. The fix also introduced a key-tag mode, where Bob sends fixed-size BLAKE3 membership tags instead of ciphertexts, dropping finalisation from O(A*B) trial decryptions to O(A) hash lookups (~21x faster at 5,000 units per side) and closing the element-length side channel. Tag mode was then made the default everywhere, with BLAKE3 switched to its derive_key mode for domain separation. This was a breaking wire-format change; the JS reference demo still contains the old flaws and is now documented as visualisation-only.

Performance work followed: a multi-level mesh PSI cascade (ported from the React frontend's grid idea) intersects coarse cells first and only runs finer levels inside surviving parents, about 1.8x faster with ~46% fewer wire bytes on clustered placements; and parallelized per-element scalar loops plus a local hash-to-group cache, with careful reasoning about what is safe to cache (only the deterministic local mapping, never anything wire-visible, since a reused scalar would let the counterparty re-identify elements across runs).

The rest of the day built the dispute-resolution track: design notes with corrected provenance (the commit-and-replay architecture from the 2020 blog post, the seed-derivation binding from the xaya/fog-of-war reviewers' security review, Truebit/Cartesi/Xaya channels as verification-game influences), then a full draft commit-reveal spec (key/seed hierarchy, per-turn commitments, signed flights, seed-derived padding, the byte-exact audit algorithm and its soundness argument). Spec iterations resolved seed-opening granularity via per-turn commitment binding, split the design into two deployment profiles (GSP-arbitrated on Xaya vs channelized), and restricted PSI to unfriendly pairs. Phase 1 of the implementation plan then landed: deterministic derivation mode, seed-derived padding and commitment helpers, a signed append-only transcript container, a recorded-session helper, and a psi_audit CLI that recomputes the accused party's flights byte-for-byte and prints an HONEST/FRAUD/SIGNATURE-INVALID verdict, all covered by tests including forged-transcript fixtures. GitHub Actions CI (build, unit tests, smoke and bench self-checks) went in the same day, alongside README cleanup.

**Decisions & notes:** The reveal-randomness audit is only sound now that hash-to-group has unknown discrete logs; under the old H(x)*G construction it was forgeable with one modular division. Randomness is never parallelized or cached: scalars and nonces are generated in serial stages, and the parallel workers write by index so wire bytes stay identical to the serial path. Phase 1 spec TBDs fixed in code: 16-byte gameId, BLAKE3 derive_key with context PSI-commit-v1 as the commitment hash, N_max carried in the opening file until a chain-side parameter store exists.
